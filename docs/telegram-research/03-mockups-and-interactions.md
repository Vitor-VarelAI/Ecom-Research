# 03 — Mockups e interação

Razão de existência: mostrar o resultado móvel antes de definir código ou preencher dados que ainda não existem.
## Regras do mockup
- Uma mensagem inicial e uma mensagem por produto.
- `AVANÇAR` continua a ser sinal advisory, não decisão final.
- O gate é progressivo: falta documental pode bloquear venda sem bloquear descoberta, pesquisa de fornecedor ou um teste sem checkout.
- Bloqueios duros ficam reservados para risco material, proibição ou propriedade intelectual antes da publicidade.
- Não existem imagens validadas de fornecedores, logo os cinco exemplos são enviados sem media.
- Não existe URL pública do relatório, logo o botão correspondente não aparece.
- URLs e botões externos só aparecem quando forem validados.
- O Legal Gate desta fase cobre UE/Portugal. PT, GB e US são prioridades comerciais de fornecedor/shipping; GB e US ficam fora do âmbito jurídico desta fase.

## Botões externos
Cada linha tem no máximo dois botões. Um botão inexistente é omitido, não desativado.

```text
[ Ver produto ] [ Ver prova global ]
[ Google Trends ] [ Google Shopping ]
[ TikTok Creative Center ] [ Meta Ads Library ]
[ Ver concorrência ] [ Ver Safety Gate ]
[ Ver legislação ] [ Ver documentação ]
[ Ver fornecedor ] [ Comparar fornecedores ]
[ Procurar BigBuy ] [ Procurar CJ ]
[ Procurar AliExpress ] [ Procurar Alibaba ]
[ Calcular margem ] [ Pedir amostra ]
```

O botão `Ver relatório completo` permanece ausente até existir URL pública validada.

## Botões de decisão
```text
[ Aprovar ] [ Observar ]
[ Descartar ] [ Guardar para depois ]
[ Pedir validação legal ] [ Pedir novo fornecedor ]
```

Os botões usam tokens opacos curtos. `Aprovar` aprova apenas a próxima fase indicada na mensagem, nunca uma autorização genérica de venda. O servidor resolve o token para produto, semana, mercado, fase e ação; os dados completos não são colocados em `callback_data`.
